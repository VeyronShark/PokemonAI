UNDER THE POKÉ BALL

How Poké AI works

An agentic generative AI system that routes questions to data and task-specific tools, then turns their results into a useful answer.

The shared architecture

  1. 01
    You ask

    The browser sends your message and recent conversation history to the FastAPI /chat endpoint.

  2. 02
    The agent decides

    Qwen3:4b (served by Ollama) reads the request and available function descriptions, then chooses whether to answer directly or call a relevant tool.

  3. 03
    Tools ground the answer

    Python executes the requested data lookup or task logic. Results are returned to the model as context; the model can request more tool work before it responds.

  4. 04
    The UI renders it

    The model writes the user-facing text. The API also sends structured task data when needed, so the browser can render Pokémon cards, teams, or an interactive battle.

Why this is agentic: the model chooses and sequences tools based on the request. It does not calculate every fact itself: deterministic code and retrieved data provide grounding, while the model interprets the request and explains the result.

THE AGENT'S TOOLBOX

Tools the agent can call

Qwen selects the tools that fit your request; not every question needs every tool.

  • get_pokemon

    Fetch a Pokémon’s types, abilities, measurements, base stats, and artwork from PokéAPI.

  • analyze_team_coverage

    Measure a selected team’s defensive weaknesses and missing offensive type coverage.

  • simulate_battle

    Prepare two Pokémon’s sprites, stats, move sets, and estimated damage for a battle.

  • search_knowledge

    Retrieve relevant passages from the local Pokémon knowledge base.

  • web_search

    Find current or external Pokémon information on the internet.

  • fetch_web_page

    Read a selected webpage in detail after finding it in web search.

📘

1. Pokémon lookup · PokéAPI

For a question about a Pokémon’s known facts, the agent can call the Pokémon data tool.

  1. For a factual lookup, the agent calls get_pokemon with the Pokémon’s name. The backend normalizes it, resolves the PokéAPI identifier, and fetches its record.
  2. The tool returns structured facts—types, abilities, measurements, base stats, and artwork. Those results ground the model’s answer.
  3. If the question needs locally stored context or current external facts, the agent can also use search_knowledge or web_search followed by fetch_web_page.

PokéAPI and retrieved sources supply the evidence; the language model supplies the conversational explanation.

🧭

2. Team builder · coverage + recommendations

The model keeps the Pokémon you chose, asks the analyzer to assess that core, then recommends additions.

  1. The agent calls analyze_team_coverage with only the Pokémon you selected—not names it plans to recommend.
  2. The analyzer fetches their data and calculates shared defensive weaknesses, possible resistances, and uncovered offensive types using the type chart.
  3. The model uses those results to recommend exactly enough distinct additions to reach six, without replacing your selected Pokémon.
  4. A follow-up extraction step resolves the recommended names to Pokémon data and sprites. The API checks that all six team members have displayable sprites before returning the structured team.

Coverage calculations are deterministic; choosing complementary additions and explaining the roster are generative steps grounded in those results.

⚔️

3. Battle simulator · prepared by data, played in the UI

The agent prepares two Pokémon for battle; the browser animates a deliberately simplified matchup.

  1. The agent calls simulate_battle with both names. The backend fetches their stats and battle sprites from PokéAPI.
  2. For each Pokémon, it checks up to 25 learned moves, retrieves damaging move details, estimates damage at level 50, and picks up to four strong moves, favoring distinct move types.
  3. The API returns names, sprites, HP, and precomputed move damage as structured battle data. The model’s text is constrained to a short introduction.
  4. When you press Start battle, the browser applies each Pokémon’s strongest precomputed damage simultaneously every 1.5 seconds, updates HP bars, and declares the result when someone faints.

This is an illustrative matchup, not a full Pokémon game engine: playback does not choose moves per turn or model every battle mechanic.
